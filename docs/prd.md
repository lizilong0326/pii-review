# 个人信息复核器（PII Review）—— 知识准入脱敏复核工具 PRD

状态：拟立项，尚未开发。使用合成数据演示；本项目提供复核辅助，不作完整合规认证。

## 为什么值得做

你做过经销商知识准入中的个人信息处理。文档进入知识库前，「自动检测到了什么、遗漏在哪里、谁确认发布」是能直接展示产品判断和交付能力的切口。做一个小而完整的复核器，比笼统谈隐私更有简历说服力。

## 目标用户与场景

资料管理员上传培训材料、客户沟通样例或售后记录，需要先识别电话号码、证件号、姓名、地址等可能的个人信息；审核人要看原文位置、拟处理方式与例外原因，再决定导出脱敏版。原始资料、脱敏版和审核记录必须能对应，但公共演示仓库只放合成样本。

## MVP 功能

1. 导入 PDF、DOCX、图片中的两类格式即可起步；解析时保留页码、段落或坐标，解析失败应显式提示。
2. 规则匹配与可替换识别器标记候选字段，区分「高把握命中」和「需人工判断」；不默认删除所有数字。
3. 左右对照原文与脱敏预览。审核人逐项选择遮盖、替换、保留或误报，并填写理由；批量操作也保留逐项记录。
4. 导出脱敏文件与审计清单，记录文件摘要、规则版本、处理项、复核时间和结果；原文默认只在本机处理，支持主动清理。
5. 用固定合成样本跑漏检和误报回归，重点覆盖断行电话、图片 OCR 错字、同名实体和地址上下文。

首版先做本地单用户；不做云端上传、自动发布知识库或「100% 脱敏」的承诺。

## 开源借力与独立贡献

用 Docling 处理文档结构，可选 PaddleOCR 处理图片文字。独立开发可审阅的证据定位、复核状态、导出与回归题集。组件各自的模型文件和依赖许可须在选定版本后核查，不能只看仓库顶层 LICENSE。

## 可验证的验收

- 20 份合成样本涵盖电话、证件号、地址、普通编号与 OCR 错字，能逐项查看命中位置和复核结果。
- 导出文件不含已确认遮盖的原文片段；对未处理项、解析失败页和低置信候选有醒目标记。
- 中断后恢复时不会把未审核项误标为已通过；同一文件重复导入可识别版本或重复记录。
- README 和演示视频解释漏检边界，不保存真实个人资料或真实客户录音。

## 实施顺序与简历证据

先做文档定位与合成题集，再做检测规则和人工复核，最后做导出与历史记录。完成后可在简历呈现「围绕知识准入设计并实现可定位、可复核、可追溯的脱敏工具」；检测召回率与误报率只在固定题集测量后写入。

## 主要风险

OCR 可能丢字，隐含个人信息可能不符合规则，人工审核仍是发布前的责任点；本机缓存、临时文件与导出路径也需纳入清理设计。

## 已确认决策（V2，替代上述待确认项）

1. 做成标准：20 份合成样本逐项可查命中位置与复核结果；导出文件不含已确认遮盖的原文片段；未处理项、解析失败页、低置信候选有醒目标记；中断恢复不把未审核项误标为已通过；同一文件重复导入可识别版本或重复记录。
2. 召回率与误报率不作硬验收数值，只在固定题集测量后写入 README（内部参考线召回率不低于 90%，不对外承诺）。
3. 20 份合成样本构成：电话 5、证件号 4、地址 4、普通编号 3、OCR 错字 4，覆盖断行电话、同名实体、地址上下文；正例用 JSON 标注文件。
4. 漏检边界口径：规则只覆盖电话、证件号、姓名、地址的常见形态；隐含个人信息、非标格式、OCR 丢字会漏检；人工审核是发布前的责任点。
5. 交互方式：审核人交互式逐项复核；首版为本地 Web UI（浏览器左右对照原文与脱敏预览），本地单用户。
6. 实现语言与运行环境：Python 3.11+，本地单进程 + 本地 Web 服务。
7. 外部依赖仅两个：Docling（文档结构解析，本地库）与 PaddleOCR（图片文字识别，可选，本地库）；无云端上传、无第三方 API。
8. 识别规则集版本化存储为 YAML/JSON，随代码分发；「可替换识别器」为规则型识别器（正则）加可插拔的模型型识别器接口（预设一个启发式实现）。
9. Docling 与 PaddleOCR 按锁定版本记录到 README（含版本号与许可证），核查结论在选定版本后填入。
10. Docling 与 PaddleOCR 均为本地库直接 import 调用，不通过 MCP 协议或插件机制接入。
11. 安全红线：原文仅本机处理、不上传云端；本机缓存、临时文件与导出路径纳入主动清理；首版不自动发布到知识库。
12. 降级策略：解析失败显式提示并标记该页；OCR 丢字降级为「低置信·需人工判断」；识别器失败标记为「未处理」而非「通过」。
13. 醒目标记方式：审计清单与导出文件中用 [未处理]、[低置信]、[解析失败] 显式标记；导出不阻断，仅标记。
14. 文档规模：首版单文件、小于 50 页；会话短，无需长会话管理与上下文压缩。
15. 断点续跑：首版需要；用本地状态文件持久化任务状态，中断恢复不把未审核项误标为已通过；不做跨会话用户偏好记忆。
16. 不需要子 Agent（单文档、无上下文爆炸）、不需要技能加载（规则集小，直接加载）、不需要上下文压缩（会话短）。
17. 审计清单格式：JSON（机器可读）+ HTML（可读）；字段包括文件 SHA256 摘要、规则版本、处理项、复核时间、结果。
18. 重复导入识别：按文件 SHA256 摘要索引历史记录；重复导入时提示已存在记录。
19. 权限系统：清理动作会删除本机文件（破坏性操作），需内置权限控制（路径白名单校验、删除前确认、审计日志），属必备权限能力。
20. 触发方式：资料管理员导入文档后，系统自动触发解析与候选标记流程，无需逐次人工确认。
21. 姓名识别规则形态：常见姓氏词典 + 上下文启发式（「姓+名」结构、称谓后缀「先生/女士/老师」）；首版不做完整命名实体模型，姓名类候选一律标「需人工判断」。
22. 地址识别与标注标准：按「省/市/区/路/号」结构 + 上下文词（地址、住址、位于）识别；20 份样本的正例边界在 JSON 标注文件中逐字段定义。
23. 本地状态文件与审计清单存储位置：项目 `.state/` 目录，按文件 SHA256 建子目录；纳入主动清理范围。
24. 遮盖替换形式：默认占位符替换 `[已遮盖:电话]`、`[已遮盖:证件号]`、`[已遮盖:姓名]`、`[已遮盖:地址]`；审核人可逐项改选保留或误报。
25. 首版支持格式：PDF、DOCX、图片（PNG/JPG）三类；Docling 解析 PDF/DOCX，PaddleOCR 解析图片；满足「至少两类」起步要求。
26. 召回率/误报率口径：按字段计——召回率 = 命中标注正例字段数 / 标注正例字段总数；误报率 = 误报字段数 / 候选命中字段总数；在固定题集上测量后写入 README。
27. 可插拔识别器的模型来源：首版纯本地启发式实现，不默认加载任何外部模型文件；模型型识别器只留接口，后续接入时再核查许可。
28. 时延与并发：单文件小于 50 页，解析 + OCR 总耗时目标小于 2 分钟（本地）；无并发要求，单文件顺序处理。
29. 角色关系：本地单用户，资料管理员与审核人为同一人，不区分账号。
30. 启动方式：一条命令 `python -m pii_review serve`，默认 http://127.0.0.1:8000；端口、数据目录、规则版本等配置外置到 config.yaml / .env。
31. 超时阈值：单页解析/OCR 超时 30 秒；单文件整体超时 5 分钟；超时或失败标记该页为「解析失败」并继续，不中断整体流程。
32. 测试框架：pytest；用例覆盖六条验收标准——核心循环单测、识别规则单测（漏检/误报固定样例）、权限边界测试（清理路径白名单）、断点恢复测试、重复导入测试、导出不含已遮盖片段测试。
33. 审计实现：审计清单由导出步骤直接产出，基于持久化状态记录支撑；复核时间、处理项与结果全部落盘可追溯。
